# P008 — validated drafting on a real task

One bounded drafting worker produced two JSON artifacts with actual final-byte validation and independent content and letter-PDF acceptance. The supervising controller subsequently completed the external application: one submit click was recorded, the portal confirmed receipt, a matching email arrived, and the singleton tracker was read back. Four locally hashed attachments matched the filenames visible in the portal. This does not independently verify server-side attachment bytes or establish an exactly-once submission mechanism.

The native worker used **Claude Opus 5**, with **xhigh configured**, for **one build and no worker repair**: **USD1.2040785**, **271938 reported tokens**, **229.016 seconds**. Token accounting includes input, output, cache reads and cache creation. Controller/reviewer usage, preparation, unsuccessful exports, evaluation and human time remain unknown. These figures are execution usage, not the full task cost. [Indexed record](P008-validated-drafting.json).

The route reused the validator and rendering work from [P005](APPLICATION-PREPARATION.md), with the local form-validation context described in [P007](FORM-VALIDATION.md). Those earlier tasks are not controlled comparators. No performance gain or milestone promotion follows from this observation.
